## AI Image Detection Fundamentals

**Pattern:** A challenge hands you an image (or a set of images) and asks "is this AI-generated?", "which one is AI?", or "what tool made this?". There is no single reliable detector — treat each method as one weak evidence line and combine them.

**Evidence classes, strongest first:**

1. **Generator metadata leaks** — near-proof when present: `Software` fields ("Stable Diffusion", "NovelAI", "Adobe Firefly", "Midjourney"), embedded generation parameters (see [Prompt / Seed Traceback](#prompt--seed-traceback-from-generator-metadata)), C2PA manifests (see [Provenance](#provenance-c2pa-content-credentials)).
2. **Binary/chunk forensics** — PNG `tEXt` parameters chunks, leftover workflow JSON, unusual chunks. Proof-level when found.
3. **Statistical image cues** — FFT spectrum shape, local smoothness, noise absence. Model-dependent; a weak/moderate signal.
4. **C2PA / watermark / provenance** — proof-level only when a manifest or watermark payload is actually present.
5. **Visual human judgment** — deformation, text errors, lighting physics. Experience-dependent, weakest as machine output.

**Key insight:** AI-generated content is a *solver-created artifact*: unlike a camera photo it is rendered from latent noise, so it carries the generator's conventions (and often the generator's own metadata) rather than physical-world traces like sensor noise. Before running any statistics, spend two minutes on cheap decisive checks: `exiftool`, `strings`, chunk listing. Most CTF "AI image" problems are solved by metadata, not by deep learning research.

## Error Level Analysis (ELA): Where It Works and Fails

**Pattern:** A classic tool for "is this photo edited?" questions. ELA re-saves the JPEG at a fixed quality and highlights pixels whose error is high; regions that were re-compressed at a different quality (double-compressed, or spliced from another image) light up.

```bash
# Local Python equivalent: re-save at quality 75 and diff
python3 - <<'EOF'
from PIL import Image
import numpy as np

Image.open("img.jpg").convert("RGB").save("/tmp/ela_resaved.jpg", quality=75)
a = np.asarray(Image.open("img.jpg").convert("L"), dtype=float)
b = np.asarray(Image.open("/tmp/ela_resaved.jpg").convert("L"), dtype=float)
Image.fromarray(np.clip(np.abs(a - b) * 8, 0, 255).astype(np.uint8)).save("ela.png")
EOF
```

The web tool `forensically` (fotoforensics.com) wraps the same idea (ELA + "ghost" for double-compression) in a GUI.

**Honest limitation — say this plainly in any report:** ELA measures *compression history differences*, not authenticity. An AI image is generated pixel-by-pixel (or decoded once from latent space) and has no camera-capture pipeline, so its error level is typically uniform and low across the whole image — ELA output is flat and **cannot flag an AI image as AI**. For the binary question "generated by AI or not", ELA is effectively useless as a primary detector.

**Where it does help:** only when the artifact is a *composite* — e.g. a real photo with an AI-regenerated region pasted in, or a crop re-saved at a different quality — because then different areas carry different compression histories. Heavy social-media re-encoding destroys the signal entirely.

**Related:** `jpegsnoop` reports the JPEG encoder/quantization tables; a "photo" encoded by generic `libjpeg`-style tables (rather than a camera model's table) is another weak AI/photomanipulation hint, not proof.

## GAN and Diffusion Generator Fingerprints

**Pattern:** The generator architecture leaves statistical traces in the pixels; look for them with a 2D FFT and local statistics.

**GAN checkerboard artifact:** transposed convolution with a kernel size not divisible by the stride produces uneven overlap, a periodic ~2px grid in flat regions. In the frequency domain this appears as sharp periodic peaks near the Nyquist radius of the FFT magnitude image. Modern GANs (StyleGAN) use blur+upsample and usually do not show it — absence is not evidence of authenticity, and any resizing/JPEG grid artifact can fake a checkerboard.

**Diffusion fingerprints:** no single clean signature. Common second-order observations: over-smoothed microtexture, reduced high-frequency energy (steep spectral rolloff), and "waxy" uniform color patches. Latent-space diffusion (SD/SDXL) can leave faint blocky or positional color-covariance structure after decode; worth an FFT look, but treat it as a supporting indicator only.

```python
# Radial power spectrum: real photos decay gradually (~1/f), diffusion output
# often rolls off faster; GAN checkerboard shows periodic peaks at max radius
import numpy as np
from PIL import Image

im = np.asarray(Image.open("img.jpg").convert("L"), dtype=float)
F = np.abs(np.fft.fftshift(np.fft.fft2(im - im.mean())))
yy, xx = np.indices(im.shape)
r = np.hypot(yy - im.shape[0] // 2, xx - im.shape[1] // 2).astype(int)
profile = np.bincount(r.ravel(), weights=F.ravel()) / np.bincount(r.ravel())
print("radius,log-power")
for i in range(0, len(profile), max(1, len(profile) // 40)):
    print(i, round(float(np.log10(profile[i] + 1e-9)), 3))
```

**Key insight:** report the *shape* of the spectrum (gradual decay vs steep rolloff vs periodic spikes), never a single number as a verdict. These cues are model- and dataset-dependent; combine them with metadata checks before claiming "AI".

## Sampler / CFG Parameter Traces

**Pattern:** Deterministic generation parameters leave subtle pixel signatures, but they are **not reliably automatable** with a short script — use them as human-judgment clues and, more importantly, as strings to grep for in metadata.

**Classifier-free guidance (CFG):** CFG amplifies the difference from the unconditional prediction, which overshoots: high CFG values produce sharpened, oversaturated edges (halo-like ringing) and flatten low-detail regions into uniform color. High CFG + few steps yields a "burned", contrasty look; low CFG yields washed-out, soft images.

**Samplers:** ancestral samplers (Euler a, DPM++ 2M Karras...) add per-step noise and differ from deterministic ones (DDIM, Euler) in residual high-frequency noise texture. Comparing two images generated with identical seed/prompt but different samplers shows this, but there is no practical "which sampler?" detector for CTF scale.

**Practical use:**

```bash
# Where the parameters actually live (see Prompt/Seed section for full parsing):
exiftool -Parameters -Software -All img.png | head -30
strings -a img.png | grep -iE "sampler|cfg scale|steps|seed" | head
```

**Key insight:** CFG/sampler analysis is mostly relevant when (a) you have a *reference* regeneration to compare against, or (b) the parameters leak in metadata and you must reason about whether the claimed generation is plausible (e.g. metadata says `Steps: 5, CFG scale: 1` but the image has heavy detail — inconsistent, likely touched up afterward).

## Diffusion-Specific Visual Markers

**Pattern:** Certain failures are common to diffusion outputs and make good human-judgment and simple-statistics clues. None is a proof on its own.

**Noise distribution:** a real photo has photon shot noise — per-pixel standard deviation grows with brightness, and even flat areas (sky, walls) retain sensor noise. Diffusion output is generated from Gaussian noise by iterative denoising; flat regions end up near noiseless, with variance collapsing to ~0.

```python
# Per-block stddev map: many dead-flat blocks in photo-like content = suspicious
import numpy as np
from PIL import Image

im = np.asarray(Image.open("img.jpg").convert("L"), dtype=float)
h, w = im.shape
bs = 16
grid = im[: h // bs * bs, : w // bs * bs].reshape(h // bs, bs, w // bs, bs)
stdmap = grid.std(axis=(1, 3))
print("blocks:", stdmap.size, "| std<2.0:", int((stdmap < 2.0).sum()),
      "| std<1.0:", int((stdmap < 1.0).sum()))
# A real photo rarely has many sub-2.0 blocks except legitimately uniform
# subjects; a "photo" full of them is a weak AI clue.
```

**Local over-smoothing:** skin, backgrounds and bokeh rendered as smooth gradients with no grain — the "plastic" look. Check teeth/eye boundaries, hair strands, fabric weave.

**Text rendering errors:** diffusion models garble text — merged or wrong letters on signs, labels, shirts. Crop the region and OCR it (`tesseract`); garbled predictions where the context demands clean text is a strong clue. Newer models (SDXL, MJv6) are much better; weak alone.

**Structural deformities (human judgment):** extra/missing/fused fingers, wrong finger counts on both hands, asymmetric ears/teeth, unrealistic reflections (both eyes reflecting identical highlights), eyeglass-glare and jewelry refraction that violate physics, background perspective inconsistent with foreground. Zoom into hands and eyes first.

**Key insight:** newest public models fix most of these, so *absence of artifacts is not evidence of authenticity* — never argue "no deformities, therefore real". These clues only *support* an AI finding; the decisive evidence is usually metadata or a watermark.

## AI Audio Detection

**Pattern:** A challenge gives a WAV/MP3 of speech and asks "is this a real recording or TTS/voice-clone?", or asks which track is synthetic out of several. Principle-based checks beat any published "AI detector" for CTF scale.

**Spectrogram smoothness:** real speech has irregular fricative noise, formant jitter, breath and lip-noise; TTS/cloned voice has unnaturally clean, uniform formant tracks and little high-frequency variation.

```bash
sox voice.wav -n spectrogram -o spec.png        # render spectrogram (eye check)
sox voice.wav -n stat                           # global duration/RMS sanity
```

**Missing silence segments:** TTS pipelines trim leading/trailing silence and clamp inter-word gaps; real recordings keep room tone and natural pauses.

```python
import wave, numpy as np

w = wave.open("voice.wav"); sr = w.getframerate()
data = np.frombuffer(w.readframes(w.getnframes()), dtype=np.int16)
frame = sr // 100                               # 10 ms frames
amp = np.abs(data[: len(data) - len(data) % frame].reshape(-1, frame)).mean(axis=1)
sil = amp < amp.max() * 0.02
ed = np.diff(np.concatenate(([0], sil.astype(int), [0])))
gaps = (np.where(ed == -1)[0] - np.where(ed == 1)[0]) * 10  # ms
print("silence ratio: %.3f" % sil.mean())
print("pause lengths (ms):", sorted(gaps)[:15])
print("leading silence (ms):", int(gaps[0] if sil[0] else 0))
# TTS: no leading silence, unnaturally short and regular pauses
```

**Breathing anomalies:** no inhalation before phrases (nothing to hear over), or perfectly periodic "breaths" in cheap clones. A real recording of a human almost always contains some breath, mouth noise or room tone.

**Vocoder/residual artifacts:** old TTS/neural vocoders leave a periodic "warbling" buzz at harmonic frequencies and a robotic high-frequency residue; feed the band-passed residual back into a spectrogram to see periodicity.

**Reference comparison (the strongest check):** if the challenge implies a specific human speaker, compare acoustics:
`python3 -m pip install --break-system-packages praat-parselmouth` and measure f0 distribution and formant centroids (F1–F3) of the suspect vs any reference clip — a voice-clone has the *timbre* of the target but atypical prosody and no coarticulation noise. Transcribing with `whisper` is also a sanity check, not a verdict.

**Honest note:** one-shot synthetic-speech detection accuracy is not reliable; stack several weak signals and prefer relative comparison with a reference when you have one.

## Provenance: C2PA Content Credentials

**Pattern:** Tools that join C2PA (Adobe Firefly, Generative Fill, newer camera apps, Midjourney v6+ opt-in) embed a signed *manifest* — the "Content Credentials" badge you see on web images. The manifest records what tool created/edited the asset, its ingredients (source files), and a signature chain. Inspect it; CTF flags hide in it.

**Where C2PA data lives:** JPEG — JUMBF in an APP1 marker (`C2PA`); PNG — `iTXt` chunk key `c2pa`; MP4 — a `c2pa` box; also *remote manifests* referenced by URL instead of embedded.

```bash
# Official CLI (Rust): c2patool  https://github.com/contentauth/c2pa-rs
cargo install c2patool                 # or prebuilt binaries from GitHub releases
c2patool img.jpg                       # print manifest JSON to stdout
c2patool img.jpg -d                    # detailed internal C2PA structure
c2patool img.jpg --info                # overview + validation status
c2patool img.jpg --tree                # manifest store tree (assertions, ingredients)
c2patool img.jpg --certs               # PEM certificate chain of the signature
c2patool img.jpg -o ./report           # dump manifest + thumbnails/ingredients
```

```python
# Official Python binding: pip package "c2pa" (contentauth/c2pa-python)
python3 -m pip install --break-system-packages c2pa

from c2pa import Reader
with Reader("img.jpg") as r:
    store = r.json()                   # full manifest store
m = store["manifests"][store["active_manifest"]]
print(m.get("claim_generator"))        # e.g. "Adobe Firefly", "c2pa_test/0.1"
print(m.get("signature_info"))         # alg + cert chain info
print(m.get("assertions"))             # c2pa.actions, c2pa.created/edited, ...
```

**Key fields:** `claim_generator` (the tool); `c2pa.actions` with IPTC digital source types — `digitalCapture` (camera) vs `trainedAlgorithmicMedia` (AI model) vs `compositeWithTrainedAlgorithmicMedia`; `ingredients` (source assets with their own data — classic CTF spot: the *prompt or flag in an ingredient title*); `thumbnail` assertions (embedded preview that may contain a hidden image). A remote manifest means fetching `manifest_uri` over HTTP.

**Honest caveats:** manifest *presence and valid signature only prove the chain to the claiming tool's certificate* — anyone can embed a manifest claiming anything (even self-signed certs), and stripping C2PA metadata via re-encode or screenshot is trivial. Absence proves **nothing**; a valid C2PA signature is evidence of *what a tool says happened*, not of authenticity.

## Latent Watermarks (Invisible AI Watermarks)

**Pattern:** AI services embed an imperceptible *payload* into the image at generation time, readable only with the matching detector/decoder. If the challenge supplies a detector (or model weights), extraction is the solve: run it over every candidate image and compare payloads.

**How it works:** a trained encoder+decoder pair (often DCT-domain, e.g. Google SynthID) perturbs pixels or the latent so the payload survives resizing/compression; a *different* model family (Meta Stable Signature, Watermark-RT) trains a decoder on top of a watermarking layer. Detection = feed the image through the decoder and read bits; you need the detector (or key) — detection is not public knowledge for most systems.

**CTF patterns:**

- Detector weights provided → `torch.load` and scan all candidates; the flagged image (or unique payload = "flag") is the answer.
- Same payload across several candidate files → they share a generator/batch: fine-grained source identification.
- "Watermark is present" from the official detector of a named service → combined with metadata, this is the strongest single AI signal you can cite.

**Key insight:** a watermark finding is proof-level *when the detector is available*; without the decoder, an invisible watermark cannot be recovered by eyeballing or FFT, and guessing a private watermark key is not a CTF-expected path (that would be a dedicated crypto/reverse challenge).

## Prompt / Seed Traceback from Generator Metadata

**Pattern:** Local Stable Diffusion UIs dump the *entire generation configuration* into the image. Recovering it gives the prompt (frequently the flag itself), the seed, and a reproducible regeneration.

**Where it lives:**

- **AUTOMATIC1111 / stable-diffusion-webui:** PNG `tEXt` chunk, key `parameters` — plain text: `Prompt`, `Negative prompt`, `Steps`, `Sampler`, `CFG scale`, `Seed`, `Size`, `Model hash`, `Model`, `Denoising strength`, hires-fix params.
- **ComfyUI:** PNG `tEXt` chunks `prompt` and `workflow` — JSON graph including positive/negative prompt text, seed, and checkpoint name.
- NovelAI/Midjourney scrub most metadata — their absence is the norm, not a clue.

```bash
exiftool -all img.png | grep -iE "parameters|prompt|software"
pngcheck -v img.png                     # chunk list; spot tEXt/zTXt/iTXt
strings -a img.png | grep -iE "seed|sampler|cfg|steps|negative|model" | head
```

```python
# Minimal PNG text-chunk reader (tEXt; zTXt is zlib-compressed after the key)
import struct

def text_chunks(path):
    out, data, pos = {}, open(path, "rb").read(), 8
    while pos < len(data):
        ln, typ = struct.unpack(">I4s", data[pos:pos + 8])
        chunk = data[pos + 8:pos + 8 + ln]; pos += 12 + ln
        if typ in (b"tEXt", b"zTXt", b"iTXt"):
            k, _, v = chunk.partition(b"\x00")
            if typ == b"tEXt":
                out[k.decode(errors="replace")] = v.decode(errors="replace")
        if typ == b"IEND":
            break
    return out

print(text_chunks("img.png").get("parameters", "")[:2000])
```

**Regeneration:** with `Model hash` + `Seed` + `Steps` + `Sampler` + `CFG scale` + `Size` you can reproduce the image with the same checkpoint (webui, or `diffusers` with the matching model/scheduler). Pixel-level match → the image is unedited; mismatch → it was processed after generation (or the params were spoofed).

**Key insight:** if the challenge ships a webui/ComfyUI-generated PNG, read the `parameters`/`prompt` chunk *before* any statistics — the flag is usually the prompt or negative prompt directly.

## Practical Triage Workflow

**Pattern:** A suspected-AI image (or audio) arrives. Run these in order; stop as soon as a decisive piece of evidence answers the question.

1. **Identify container + all metadata**
   ```bash
   file img
   exiftool -a -u -G1 img          # Software, Generator, no Camera/EXIF, C2PA
   ```
   Look for: `Software: Stable Diffusion / NovelAI / Adobe Firefly / Midjourney`, absence of camera make/model, JFIF vs EXIF.

2. **Binary / string scan for generator residue**
   ```bash
   pngcheck -v img.png             # PNG chunk structure, text chunks
   binwalk img                     # appended payloads / overlays
   strings -a -n 6 img | grep -iE "seed|sampler|steps|negative|comfy|workflow|model_hash" | head -20
   strings -el -n 6 img | head     # UTF-16 (strings default misses it)
   ```

3. **Generator-params extraction** — `parameters` tEXt (A1111), `prompt`/`workflow` (ComfyUI); see [Prompt / Seed Traceback](#prompt--seed-traceback-from-generator-metadata). Try regeneration if a seed+model are found.

4. **Statistical checks** — radial power spectrum + per-block stddev map (dead-flat blocks, steep rolloff, periodic checkerboard peaks); see [GAN/Diffusion Fingerprints](#gan-and-diffusion-generator-fingerprints) and [Visual Markers](#diffusion-specific-visual-markers). JPEGG: run ELA *only* when a composite/splice within real photos is plausible, and remember its flatness proves nothing ([ELA](#error-level-analysis-ela-where-it-works-and-fails)).

5. **Provenance / watermark** — `c2patool -d --tree --certs`; extract `-o ./report` ingredients/thumbnails; run any provided watermark detector over all candidates ([C2PA](#provenance-c2pa-content-credentials), [Watermarks](#latent-watermarks-invisible-ai-watermarks)).

6. **Audio branch (if WAV/MP3)** — spectrogram smoothness, silence-gap statistics, breathing, f0/formant comparison against a reference ([AI Audio](#ai-audio-detection)).

7. **Assemble the evidence chain and state limits** — log each finding as *proof-level* (metadata chunk, C2PA `trainedAlgorithmicMedia`, watermark payload) vs *weak/statistical* (spectrum shape, smoothness) vs *visual judgment* (deformities). Never write "AI-generated" from statistics alone; the final claim should name the strongest supporting evidence and what it does/doesn't prove.

## CTF Scenario Checklist

**Typical challenge shapes:**

- A "photo" with **no camera EXIF** and a `Software` field naming a generator — check metadata first (also see `disk-and-memory.md` if the file came from a memory dump).
- **"Which of N images is AI-generated?"** — diff the metadata across all files, then run the FFT/smoothness checks pairwise; the odd one out is usually obvious from a missing `Parameters`/camera block.
- **Obvious deformities** (hands, text, ears) — human-judgment clues; pair with at least one machine check before reporting.
- **Audio too clean** — spectrogram + silence statistics; if the voice claims to be a named person, fetch a reference sample and compare formants.
- **Deepfake video** — extract frames (`ffmpeg -i v.mp4 frames/%04d.png`): face-boundary warping, inconsistent earrings/glasses, boundary color mismatch, per-frame flicker. This is still media forensics; treat it like the image case frame-by-frame.
- **C2PA / watermark flag hunt** — `c2patool -d` + ingredient/thumbnail extraction; remote manifest URL.
- **Prompt leak** — A1111/ComfyUI PNG where the flag *is* the prompt or negative prompt.

**Cross-check before going deep:**

- If the question is *"where / what / who is this image"* — even an "AI-looking" picture — that is **reverse-image search / OSINT**, not media forensics: `ctf-osint` (Google Lens, Yandex, TinEye, `saucenao`/`iqdb` for anime). Re-route there immediately.
- Generated-image *attacks* (jailbreaking a dreamer, adversarial perturbation, model extraction, membership) → `ctf-ai-ml`.
- Hidden data inside the image/audio (not AI provenance) → `stego-image.md` / `stego-advanced.md`.
